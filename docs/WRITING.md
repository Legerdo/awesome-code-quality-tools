# 한국어 문서 작성 기준

[README](../README.md) / [기여 안내](../CONTRIBUTING.md)

독자가 도구의 역할과 사용 조건을 바로 알 수 있게 쓴다. 이 저장소는 한국어 한다체를 사용하고, 제품명과 코드 표기는 원문을 유지한다.

## 문장

무엇을 하는 도구인지 동사로 설명한다. 명사만 나열하거나 같은 말을 제목, 본문, 결론에서 반복하지 않는다. 짧은 표의 항목명까지 억지로 문장으로 만들 필요는 없다.

| 이전 표현 | 다듬은 표현 |
| --- | --- |
| 제외 도구의 추천 재유입 검사 | 제외한 도구가 추천 목록에 다시 들어갔는지 검사한다. |
| 미실행 도구의 실동작 검증 완료 표시 금지 | 실행하지 않은 도구를 검증했다고 쓰지 않는다. |
| 본체만 MIT로 분류 | MIT 표기는 도구 본체에만 적용한다. |
| 단순 내부 실행과 수정 배포는 서로 다른 검토 상황 | 내부에서 실행할 때와 수정본을 배포할 때 확인할 조건이 다르다. |

중간점으로 단어를 길게 잇지 않는다. 문맥에 맞는 조사나 쉼표를 쓰고, 내용이 길면 문장을 나눈다. 코드, 명령어 옵션, URL, 버전, 라이선스 이름, 직접 인용에 들어 있는 기호는 바꾸지 않는다.

## 의미

가능성과 확정, 미확인과 미지원, 진단과 안전한 삭제를 구분한다. 라이선스 조건과 엔진별 예외는 글을 줄이기 위해 빼지 않는다. 기능이 겹치는 두 도구를 설명할 때도 함께 쓸 수 있는지와 같은 진단이 반복되는지를 따로 적는다.

윤문 전후에 도구 ID, URL, 수치, 날짜, 지원 언어, 추천 관계, 명령어를 대조한다. 사실을 정정할 필요가 생기면 문체 수정과 구분해서 근거를 남긴다.

## Markdown

README에는 도구를 찾는 데 필요한 소개와 표를 둔다. 자세한 조건은 해당 문서로 연결한다. 표가 넓어지면 열을 늘리기보다 설명을 표 아래로 옮긴다. 목차는 목록으로 쓰고, 명령어에는 언어를 지정한 코드 블록을 사용한다.

강조는 중요한 조건에만 쓴다. 문장마다 굵게 표시하거나 제목 앞에 장식 기호를 붙이지 않는다. 표와 제목, 목록은 필요한 구조이므로 없애지 않는다.

## 검토

자동 검사는 문서 생성, 링크, 스킬 형식과 일부 회귀만 확인한다. 문장이 자연스러운지, 원래 뜻이 유지됐는지는 원문과 나란히 읽어 확인한다. 특정 단어나 기호의 개수를 AI 작성 여부의 점수로 쓰지 않는다.

[AI Slop Thresher v1.2.4의 편집 지침](https://github.com/Burntgogi/ai-slop-thresher/blob/v1.2.4/skills/ai-slop-thresher/SKILL.md)을 참고했다. 외부 스킬 파일을 복제한 것이 아니라 이 저장소에서 쓰는 기준과 예시를 별도로 작성했다. 해당 프로젝트는 자체 Apache-2.0 라이선스를 따른다.
