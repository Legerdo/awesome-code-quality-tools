# 한국어 문서 다듬기

## 읽고 범위 정하기

[문서 작성 기준](../../../docs/WRITING.md)과 수정할 문서 전체를 읽는다. 독자가 도구를 고르는 문서인지, 설치하거나 검증하는 절차인지 구분한다. 눈에 띄는 기호만 치환하지 말고 문단의 정보 순서와 문장 연결을 본다.

README와 상세표는 생성 파일이다. 도구 설명은 [catalog.json](../../../data/catalog.json), 고정 문구와 배치는 [catalog.py](../../../scripts/catalog.py)에서 수정한다. 그 밖의 Markdown은 해당 파일을 편집한다.

## 문장 편집

명사만 이어 붙인 설명은 무엇을 검사하는지 알 수 있는 문장으로 바꾼다. 같은 뜻의 수식어, 내용 없는 예고, 반복되는 주의 문구는 줄인다. 이미 자연스러운 문장은 그대로 둔다.

중간점을 쉼표로 일괄 바꾸지 않는다. 조사로 연결하거나 문장을 나누고, 실제 비교 정보에는 표를 쓴다. 제목, 목록, 코드 블록은 읽는 데 필요한 만큼 유지한다. 코드, URL, 옵션, 버전, 라이선스 이름, 인용문 안의 기호는 보존한다.

의무를 권고로, 가능성을 보장으로 바꾸지 않는다. 확인하지 못한 지원을 미지원으로 단정하지 않는다. 삭제 후보를 안전하게 삭제할 수 있는 코드로 바꾸지 않는다. 두 도구를 함께 쓸 수 있다는 설명을 하나만 골라야 한다는 뜻으로 줄이지 않는다.

## 의미 대조

수정 전후를 비교한다. ID, URL, 라이선스 분류, 도구 수, 지원 언어, 확인 날짜, 추천 관계와 명령어는 이번 요청이 단순 윤문이면 그대로여야 한다. 조건과 예외가 다른 도구에 붙지 않았는지도 확인한다.

```powershell
python scripts/catalog.py --write
python scripts/catalog.py --check
python scripts/check_skills.py
python -m unittest discover -s tests -v
git diff --check
```

테스트가 문구 전체를 비교한다면 뜻을 유지하는 변경인지 먼저 검토한다. 필요한 경우 기대 문구를 함께 수정하되, 라이선스 조건과 미검증 범위를 확인하는 검사를 없애지 않는다.

## 마무리

문서 전체를 다시 읽고 제목, 표, 링크, 코드 블록을 확인한다. 기호 개수나 테스트 통과를 자연스러운 문체의 증거로 쓰지 않는다. 실제로 고친 문장과 검사한 범위만 보고한다.
